# CyberCorp 首版实现

目标：从用户目标及已有项目材料，落下一个可独立携带的 Corp 创建能力，并在隔离项目中运行实际生成、读取与恢复工具。结果约定见 [product.md](product.md)。

## 当前实现

1. 自包含 `skills/cybercorp`：创建／接入方法、确定性文件安装、目标 repo 内的准备／工作／审查方法，以及原生 Spec／占用／上下文工具。
2. 固定远端版本的独立 checkout 入口，保留原 clone 及其 WIP。
3. `skills/corpo-launcher`：多种 CLI runtime 的启动器半成品，提供显式命令传递和用户自有 Python 适配器入口；Kiro 为具体示例。安装、登录和各 runtime 的接入选择由用户负责。
4. 本地测试覆盖新／已有项目、真实临时 Git、生成命令和 fake-CLI 接续。一次独立实例已完成隔离已有项目的创建试用；其发现的未配置共享仓库仍标 active、联网行为不清晰和交接说明重复问题已修复。
5. 公开开发约定、源代码和测试自包含。私人过程记录保留在本地忽略范围；不维护另一份人工同步的发布源码。
6. 本地 `0.1.0a3` 候选重整生成项目的阅读路径。核心仍是核对有效约定、执行占用、共享接续与独立审查；取消默认通读所有协议的路径。异常记录不接管修复，任务内修复须完成，仅暂停实际受影响动作。

## 方法阅读设计

| 当前动作 | 读取范围 |
|---|---|
| 普通实现／调查 | 入口、development-loop、work-corp、精简后的 claim-protocol 与 spec-protocol |
| 固定候选审查 | 入口、development-loop、review-corp 与 spec-protocol |
| 全项目准备 | 入口、development-loop、prepare-corp；执行原生 Issue 时再进入工作方法 |
| 创建／修改／拆分／关闭 Issue，首次或替代接受 Spec 前 | spec-authoring |
| 深入跨事项规划前 | coordination |
| 完整取数与可信时间复核后仍有历史完整性错误 | damaged-history |

租期、事件字段、重新核权、检查点／释放和单次 merge 授权留在普通执行路径。恢复细则保留在按需正文；原生状态读取、协议实现及其判定没有改变，不通过截断必需历史来省上下文。

回补准备／统筹方法中的创建与首次／替代接受动作前入口；普通执行明确每段关键写入前重核当前 Issue、有效 Spec／必需输入、claim 和实际冲突。四处文字调整使普通路径增加 47 tokens；已核对生成文本、引用目标及 skill 格式，尚未新增独立行为试验。

同一最小生成示例、按所需文件完整冷读，普通工作由约 6.8–8.4k 降到 2.55–2.59k tokens，旧 clone 约 2.83–2.88k；所有方法总量由约 8.1–9.7k 降到 5.48–5.92k。使用 o200k_base／cl100k_base 作静态比较，既包含删重和阅读分层，也包含部分中文协议改写为英文的分词差异。不是实际 runtime 账单，不含宿主指令、业务材料、源代码、对话或原生 Issue/PR/CI 输出；实际原生输出随项目规模变化。

旧项目须通过自身变更流程适配方法正文及新增链接目标，保留项目编辑和原安装溯源。版本重装仍拒绝覆盖；文件采纳与运行时实际消费分别验证。

本体 103 项、启动器 24 项回归和 5 项 skill 格式检查通过；版本更新后复跑 14 项创建测试通过。独立编码消费者从生成入口实际完成可做功能及任务内修复，记录无关疑点，只暂停必要契约冲突部分；管理侧复核产物并重跑 4 项应用测试通过。另一个独立实例运行离线回放发现坏记录，按需读取损坏历史细则并给出有条件恢复路径，没有把过期租期当接管依据。

旧版包的隔离项目重装被拒且所有文件保持；方法适配覆盖新增链接目标，保留自有编辑及原安装溯源。上述是合成任务中的实际消费及离线恢复判断，未证明真实并发接续、长期行为保持或业务价值。

## 后续验证

由不知创建历史的 Corpo 在另一个有真实目标的项目中接手有价值工作，检查隐藏输入、返工、用户介入和机制成本。多实例并发与跨机恢复按实际需要取证。Kiro 示例和用户配置的其他 CLI 各自需要真实 runtime 验证；fake-CLI 测试不能替代它。
