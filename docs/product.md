# CyberCorp

CyberCorp 帮助用户的 Agent 创建或接入一个 Corp。项目的目标、事实、工作与接续依据由仓库和原生任务系统持有；更换 Agent 后仍能继续推进，创建者可以离席。

Corp 是这样的项目组织，Corpo 是其中可替换的工作 Agent，CorpMech 是支持其协作的机制。当前以 Git 和 GitHub 原生工作面实现；没有运行实例时，项目可恢复但不会自动推进。

## 输入与结果

从用户的目标、约定范围、已有仓库／材料、任务系统和授权开始，不要求用户先写完美 PRD。已有事实面优先复用，必要的新约定在项目内形成。

结果是目标项目拥有的入口、必要协作方法、可发现的工作和共享恢复路径。生成器负责可靠落文件与辅助读取；Agent 负责目标理解、设计取舍、范围判断、材料采纳和交接验收。生成成功与 Corp 可持续工作分别验证。

## 已接受需求

| 需求 | 产品行为 |
|---|---|
| 创建者可以离席 | 目标 repo 与原生任务面足够恢复；必需材料和方法不依赖私人聊天、Vault、永久 Main 或全局 skill |
| Phase 1 可用 | 入口、方法发现、工作认领、恢复、独立审查与集成路径可用；另行以真实消费者验证协作能力 |
| Phase 2 覆盖全项目并足够开工 | 按项目实际采纳必要 Canon，推导总体交付路线、近期开发骨架和首批工作；远期保持粗略，普通设计随开发收敛 |
| 避免重复昂贵规划 | 在深入补任务／跨事项排序前发现已有承接，用原生工作作有界声明与收敛 |
| 保护已有 clone | 核实实际 remote 与固定版本，保留原现场，能从独立 checkout 消费新规则；规则更新不自动改任务 pin |
| 尽量少限制 Corpo | 按需求选择方法，普通工程判断不自动上交人工；强制约束只承担实际协作需要 |
| 持续推进阶段交付 | 阶段结果与缺口驱动 plan、work、review；形成可审整体，修正复验后核对最终交付与下一入口 |
| Owner 能参与且答复可接续 | 通用机制连接沟通、送达、答复采纳与换实例接续；项目自有、可替换的沟通卡说明如何面向该 Owner 表达 |
| 验证失败能继续处理 | 通用协作检查与项目检查各有 owner；后继者能定位实际版本、复现失败，并沿原工作继续修正 |
| 事实与权限可靠 | 共享输入、有效约定、执行占用和实际证据可核对；工具批准、责任归属与 merge 授权分开 |
| 方便启动 Corpo | 可选 CLI 启动器半成品提供调用入口和适配示例；用户掌握各 runtime 的安装、登录、模型、工具权限和原生会话接入，不成为 Corp 运行依赖 |
| 启动 prompt 足够少 | 仅保留关联标记、仓库定位、开工意图和当次 merge 边界；工作选择与协作方法在 repo |

## 交付与验收

上述阶段交付、沟通卡和验证反馈的设计要求详见[吸收规格](specs/delivery-communication-verification.md)。实现、实际采纳及验证状态由[计划](plan.md)与原生交付证据持有；产品要求不代表能力已经验收。

Phase 1 建立项目自有、可接续的协作条件。Phase 2 由 Corpo 根据目标、验收与已有成果形成或复用总体 Milestone，按价值和真实依赖选择近期重点，明确必要开发边界、维护位置、检查入口与首批可执行工作。后继者应能理解整体范围，解释先做什么、为什么、在哪里实现及如何检查，并开始推进；缺少输入只暂停实际受影响范围。

准备按整个约定范围保持广度，按实际需要细化近期工作。Canon 补齐与设计可以往返，材料存在不等于被采纳；不要求全部远期文档、内部设计或模块空壳先完成。开发持续使用同一交付依据，队列非空但主要结果缺少承接时仍须补齐。阶段数量、技术栈、文档集合及模型选择由项目决定，项目特定设计的收益也不全部归给 CorpMech。

安装和结构检查、原生工具读写、独立 Agent 消费、真实接续、多实例协作及业务价值是不同证据。首版没有证据的部分保持未验证。

## 当前实现边界

核心交付采用一个可携带的创建 skill 和 Python 标准库工具。目标项目独立拥有生成结果；重复安装保护项目后续编辑。已有机制发生冲突时由创建 Agent 在原事实面适配，不自动覆盖或运行迁移。

GitHub 是首个原生任务系统，其他平台按真实需要加入。启动器面向多种 CLI runtime，提供显式命令传递与用户自有适配器入口；Kiro 是首个具体示例，不能据此宣称其他 runtime 已完成接入或验证。各 runtime 的实际接入由用户决定，暂不引入托管运行、调度服务、人员名册或独立状态数据库。包装形态是当前可运行交付选择，尚不代表市场或分发验收。

公开的产品、实现和测试资料应足以继续开发；私人过程记录不成为依赖。实现进度由 [计划](plan.md) 持有，代码来源说明见 [source-notes.md](source-notes.md)。
