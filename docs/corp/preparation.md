## 工具、检查与外部条件

- 安装与 dry-run：Python 3.9+、Git；输入格式由创建包说明持有。Python 运行不依赖第三方库。
- 本地测试：使用 [README 开发入口](../../README.md#开发与验证)。根 unittest 入口包括启动器测试，单独跑启动器用于局部复核，不能重复累计测试数量。测试使用临时仓库和合成数据，不调用业务环境。
- 原生工作：有权读取同仓的 `gh` 认证和 Git 访问；以 API 返回的真实 Issue／PR／Milestone、评论、版本及运行结果核对。写入按当前约定和权限执行。
- 本仓 [CI](../../.github/workflows/tests.yml)在 Linux 的 Python 3.9／3.13 上执行同一个根测试入口，记录实际 checkout。它不验证真实 Kiro 或其他 CLI 的账号、模型调用及长期接续。
- CLI 真实验证：所选 runtime 自身的安装、认证和可用模型／权限。没有这些条件时，可以继续隔离实现和 fake-CLI 检查，把实际接入验证留在对应工作中。

需要新版工具链或外部依赖时，以实际报错和能力目标决定；不为本轮初始化统一安装全部 runtime。公共源码不依赖个人 Vault、试点仓库、私人日志或未共享对话。

## 后续工作与准备判断

当前整个产品的目标、两包分工、输入形式、代码维护位置和本地验证入口均有仓内来源。吸收规格提供下一轮结果、验收场景、旧规则替换和采纳边界，可供后继者据此展开工作；实际承接与版本 pin 仍须从原生事项核对。

以下分别处理，不将其合并成全项目无法开发：

- **尚待实现的产品结果**：阶段交付循环、可插拔沟通卡和通用验证反馈，按规格和实施顺序推进。
- **可在开发中决定的细节**：文档拆合、最小检查实现、合成场景规模、目标项目特有阶段和 CI 适配；不得修改已有产品承诺来消除实现困难。
- **尚待取得的行为证据**：不知创建历史的真实接续、多实例／跨机行为、各 runtime 的真实调用、长期推进效果和 Owner 理解。这些由对应实际场景取证，合成测试不能代替。
- **发布或分发决定**：许可证、正式 release 与外部安装按具体发布任务决定，不阻塞当前仓内实现，也不因源码公开而自动取得授权。

自身基础准备的独立核对、发现的缺口与处置、精确共享版本和剩余验收，记录在[原生准备事项](https://github.com/OKFin33/CyberCorp/issues/1)。准备是否通过以实际交接证据判断；本页存在本身不表示阶段已验收。
