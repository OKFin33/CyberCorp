# 0008 · 移除自述形态的验证证据

- 日期：2026-09-13
- 状态：已采纳
- 影响面：`docs/evidence/`（已删除，46 个文件）、`docs/verification-status.md`、`README.md`、`CONTRIBUTING.md`、`CHANGELOG.md`、`tests/scenarios/README.md`
- 承接：[0002](0002-remove-verification-artifacts.md) 未走完的那一半

## 决策

删除 `docs/evidence/` 全部 46 个文件。仓库 tracked 文件由 117 降至 71。

## 为什么

**一、这些材料的形态与本产品的核心主张相冲突。** [实测] 19 份 Markdown 报告中 17 份含第一人称自述（"我做了什么"、"结果如何"）。而机制层「完成以非自证的证据为准」一节的第一句就是：完成意味着 PR 存在且检查通过，**没有任何散文能断言完成**。一个把这条写成核心规则的产品，其证据目录的主体却是自述报告。

保留它们的目的是提高可信度，而它们的形态恰好是产品自己判定为不可采信的那一种。

**二、这是 0002 推理的自然结论，上一轮只走了一半。** 0002 删除了 bundle、压缩 API 记录与状态快照，理由包括"一个已经带明确范围限制的声称，用文字记录加固定提交号就足够"，以及外部零上下文审查把手工存储的产物列为第三大劝退点、原话"引发对可信度包装的怀疑"。

那条推理适用于报告本身：报告也是手工存进 Git 的自证材料，只是体积小。当时留下它们，是因为把"报告"当成了比"产物"更轻的形态，而没有检查它是否满足产品自己的证据标准。

**三、真实消费证据已经出现，合成报告的边际价值随之下降。** 2026-09-13 的首次真实采纳提供了可外部查证的证据：另一个仓库的 PR、其三项托管 CI、以及一次独立审查暴露的两处上游缺陷。那种证据不需要自存。

**四、对二次开发者没有用。** 想判断这个产品能否用的人读 README 与验证状态表；想贡献的人读贡献指引与决策记录。46 个描述历史场景的自述报告不进入任何一条路径。

## 相应调整验证声称

删除证据而保留基于它的声称会更坏。因此 `docs/verification-status.md` 重构：

- 五项由合成消费支撑的能力**移出"有证据"**，进入新增的「曾验证，但证据不随版本分发」，并写明形态是消费者自述、不能算作证据、可从 Git 历史取回。
- 「有证据」现在只剩两类：四项由自动化测试支撑，两项由真实消费支撑。

这让表格变短，而那个短是准确的——此前的长度一部分来自自证材料。

## 保留与可取回

删除只作用于当前版本。产物与报告仍在 Git 历史中：

```sh
git log --all --diff-filter=D -- docs/evidence/
git show <commit>:<path>
```

`0001` 与 `0002` 中对 `docs/evidence/` 的叙述**不修改**——它们记录的是当时的事实。
