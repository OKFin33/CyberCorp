# Prepare and hand off the project

Read the root entry, `docs/corp/README.md` and the current goal. Preserve the agreed whole-project scope and existing outcomes. Choose the smallest preparation effort that lets another Corpo understand and advance that scope.

If the user bounded the request to local creation, verify and hand off that result with the missing shared setup in `docs/corp/README.md`. Do not duplicate temporary setup status across method files or expand the request into network/publishing work.

Establish the real shared work entry within current authorization: verify the intended GitHub repository, native delivery Milestone and necessary classification, then update `docs/corp/canon-map.yaml` to their actual owners. Create minimal discoverable preparation work only if none already owns it. Read it back through the native work surface. Before deeper planning, use the bounded coordination path in `docs/corp/development-loop.md`; installation or an unresolved route does not grant external write authority.

Survey the project's major results, boundaries, development dependencies, existing sources and known gaps. Reuse and route existing owners before writing more documents. Bring necessary inputs into shared, accessible owners with their sources; do not copy private material or secrets wholesale. Correct old consumers when an accepted source changes. A successful file copy does not by itself establish adoption or cutover.

Fill actual gaps according to impact and near-term dependency. Distinguish absent material, failed routing/consumption, genuine normative conflicts, ordinary engineering choices, unclear acceptance and excessive early design. Do not demand every future implementation decision now. Unknowns should explain what they affect and where resolution comes from; they do not automatically block unrelated work or reset initialization.

Use the existing preparation Issue for outcomes and remaining work. Avoid a separate phase database or universal document checklist. Local type/shape checks are useful evidence for their scope; they cannot judge complete understanding or readiness.

Hand off when the shared goal/boundaries can be understood, required inputs are obtainable, gaps and their impact are visible, and an authorized replacement can progress meaningful work or identify a real scoped stop. Explain the whole-project judgment and relevant evidence. Important unknowns may remain if they do not invalidate that judgment. Establish the next native work that follows from it instead of preparing indefinitely.

Where an independent consumer is available and authorized, have it enter only from this repo and actual native work, without private answers. Record its result and any hidden dependency found. If this was not exercised, retain that limit instead of declaring Phase 1 or Phase 2 proven from scaffold checks.
