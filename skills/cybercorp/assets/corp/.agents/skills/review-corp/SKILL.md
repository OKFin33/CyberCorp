# Review the actual candidate

Read the entry/development loop if not loaded, then `docs/corp/spec-protocol.md`, required Canon, actual base/head and changed implementation from an independent checkout. Check readiness and related conflicts; a fixed PR review needs no artificial sub-Issue/claim.

Use a stable runtime instance ID (or generate a UUID). An implementer cannot rename itself into an independent reviewer; another non-implementing instance may share its model/team. Add affected consumer perspective for shared semantic changes, without requiring a reviewer per team.

Select checks that expose concrete errors, omissions or needless complexity; retain applicable evidence. Return actionable findings with behavior, evidence and minimum correction, or a supported no-blocker conclusion. Identify instance/non-involvement, exact base/head, Spec pin, scope, executed versus relied-on checks, and untested behavior on the existing PR.

Head or relevant Spec changes need re-evaluation; a new integration base needs compatibility and applicable checks, not reuse of the old combination's green result. Review/CI do not prove untested behavior or user value and do not grant merge authority. Follow the project's specific one-attempt PR/head/checks/method authorization.
