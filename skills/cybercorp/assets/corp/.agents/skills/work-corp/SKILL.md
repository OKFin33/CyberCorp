# Advance the result

Read `docs/corp/README.md` once per session if you have not. Each step names the `mechanics.md` section holding the rule; this file gives the order, not the rules.

## Pick your unit

- Told which Issue, or resuming your own: use it.
- Not told: the highest-priority open Issue in the current Milestone without the Owner-decision label (S4).
- Nothing qualifies: the deficit is the work. Converge on an existing planning carrier or create one (S4), then treat that as your unit.

Reviewing a PR rather than implementing is `review-corp/SKILL.md`, not this file.

## Then, in order

1. **Occupy it** (S2), before reading code or anything else.
2. **Check it carries its own acceptance** (S1). If it does not, fix the body within your authority, or take the missing decision to the Owner under the entry's governing rule. Do not implement against unverifiable acceptance.
3. **Check it fits** (S6): independently deliverable, then completable within one context window. Split now if either fails — mid-way splits cost you a write-up to the shared layer first.
4. **Implement.** Ordinary engineering choices are yours. A change to a shared premise goes to that fact's owner and to affected consumers before you build on it. For setup, version evidence, or continuing after a failure, see S3.
5. **Close out.** Run your checks rather than asserting they would pass. A PR with passing checks is completion (S3). Whether the stage is near done is not a judgement that exists here.
6. **Report back only** when something changes a shared agreement, widens your authorization, or overturns a premise this work depends on. Otherwise continue; independent parts do not wait. For Owner-facing communication see S5 and S8, and use the card the entry routes to.
7. **Stopping early** means leaving a shared checkpoint and releasing the occupation (S7), not holding it silently.

Report implemented, reviewed, merged and accepted strictly by the evidence each word has (S3).
