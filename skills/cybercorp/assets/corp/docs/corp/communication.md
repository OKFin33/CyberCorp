# Communicate and carry the reply forward

Before communicating in preparation, work, review, correction or delivery, read the current project [Owner communication card](owner-communication.md). The card changes expression, not facts, acceptance or authority. Follow effective direct Owner instructions if they conflict with it; return lasting preference changes to the actual card owner. Reuse an existing card by changing this link, not by duplicating its contents in templates.

1. Clarify the purpose: progress, recommendation, optional feedback, or a necessary decision/authorization. For a decision give the facts, recommendation, consequences and exact needed response. Continue independent authorized work; wait only on the affected scope.
2. Use the existing carrier: PR title/body/comment for a change with a PR; associated Issue or the current conversation otherwise. Material that affects subsequent work needs an accessible shared location; light discussion need not become a task. Templates should link this method/current card, not copy preferences.
3. Actually deliver through the current interactive conversation or a configured, authorized unattended channel. Project/runtime integration owns identity, credentials and sending rights. Recording a request, successful sending and receiving a reply are distinct facts. If no channel is configured, preserve the request and delivery gap; do not promise notifications or wakeups.
4. Attribute a reply: preserve responder, source channel, time, applicable scope and available source. An attributable direct reply from the authorized Owner may be transcribed by a Corpo; the Owner need not publish the same decision again routinely. If source or decision authority cannot be verified, resolve only that affected decision. Update the actual Spec/Canon and affected consumers through their change procedure. Received, adopted and executed are different states.
5. When blocked, checkpoint the shared request, delivery state, remaining scope and resume condition, then release under [claim-protocol.md](claim-protocol.md). On a reply, the same or a successor instance rechecks its authority, current agreement, artifacts and execution rights before continuing. Without a running instance, use the existing startup entry. Silence, read receipts and elapsed time never grant authority.

Link exact evidence without omitting significant failures or unknowns. A replaced card cannot remove those requirements or grant external sends, merge or other permissions. Actual Owner understanding, delivery-channel operation and successor consumption each require their own evidence.
