# Owner communication card

Project-owned starting point: adapt this document from known Owner instructions before handoff, or point the communication method at an existing equivalent. Missing preferences do not block work. Keep credentials, acceptance rules and live work state in their actual owners.

Help the Owner understand the concrete result and make the decision currently needed. Use clear, neutral language; lead with the result or recommendation, then explain the relevant change and tradeoff. State important failures, what evidence demonstrates, what remains unverified, and the exact response needed when there is one.

Choose detail for the reader's known background. Use a scenario, before/after example, diagram or demonstration when it helps explain the change. Label illustrations separately from actual run evidence; do not invent an unknown previous behavior. For engineering-only work explain the obstacle removed. Link technical evidence for inspection; do not impose a language, fixed format or reporting schedule on every project.
